1. Context & symptom

CHIMP is replacing its Meta-CSP storage layer with a CHIMP-native solver kernel. The SimpleTemporalNetwork (STN) is the native replacement for Meta-CSP's APSPSolver. A 93-problem benchmark compares behavior of the current branch against the frozen legacy-metacsp branch.

One problem stood out: RACE-serve_coffee produced an identical search tree and an identical 37-action plan on both branches, but native was roughly 1.4–3.7× slower depending on the measurement context — a pure per-node cost problem, not a search-order or correctness problem.

Debugging invariant: because the trees matched exactly (later verified: identical 91-node trees, identical plans), any timing difference had to come from inside constraint propagation — not from exploration behavior.

2. Profiling methodology

A small isolated driver solves exactly the benchmark problem repeatedly (1 warm-up + N measured), and Java Flight Recorder (JFR, -XX:StartFlightRecording=settings=profile) samples the CPU. Both leaf (self) time and inclusive time are aggregated from jdk.ExecutionSample stacks.

Before the work, a single solve cost ~1.3 s and the STN counters showed:

3. Root causes

3.1 Every constraint add ran full O(n³) Floyd-Warshall

addTimePoint() set a needsFullPropagation flag. The search materializes new temporal variables (2 time points each) on virtually every resolver application, so the next constraint add triggered a full recomputation instead of the existing incremental O(n²)-per-edge path. The incremental path almost never ran.

A fresh time point only adds INF edges plus its two origin bounds — it cannot improve any existing distance. Flagging the whole matrix as stale was simply wrong.

3.2 Infeasible constraints triggered full rebuilds

When a resolver attempt was temporally infeasible, the failing constraint's edges had already been written into the matrix, so the solver had to restore exactness with a full from-scratch rebuild. Instrumentation showed 392 of the 446 rebuilds were single-constraint add failures — the routine rejection of infeasible partial plans — not genuine retractions.

3.3 Time points were never freed (matrix kept growing)

Native removeVariable removed constraints but never released the STN time points, so timePointCount grew monotonically to 315 (and the implicit duration edges of removed intervals stayed in the constraint list forever). Meta-CSP — by contrast — frees and reuses time points (tpCreate/tpDelete), keeping its matrices compact and its rebuilds cheap.

Bonus bug found while validating the fixes: after switching to pure incremental propagation, a randomized stress test against a reference Floyd-Warshall implementation immediately caught two problems:
  1. Origin-hub closure. Every time point connects to the origin; paths like 2 → 0 → 1 are only closed by full FW. Incremental edge sweeps never revisit the (never-retightened) origin edges, leaving the matrix too loose. Fix: explicitly close through the origin each propagation.
  2. INF-sentinel overflow. The O(1) feasibility check overflowed on unbounded (±INFINITY) bounds, falsely rejecting valid constraints. Fix: guard sentinels exactly like legacy's sum() does.

4. The fixes (commit 7a9279b, 3 files + 1 new test)

4.1 Incremental adds — no more forced full propagation

addTimePoint() no longer sets needsFullPropagation; the matrix stays exact and every add is now incremental. The needsFullPropagation flag was deleted.

4.2 Exact incremental propagation to the fixpoint

propagateIncremental() now repeatedly:

  1. relaxes all pairs through every recently-tightened edge (multi-round so paths crossing several new edges compose), and
  2. closes all paths through the origin hub in O(n²) — the part full FW relabels that pure edge sweeps never revisit.

Rounds continue until nothing tightens; pathological cascades fall back to full Floyd-Warshall.

show code 
private boolean propagateIncremental() {
    int n = timePointCount;
    for (int round = 0; round < 4; round++) {
        boolean changed = false;
        for (int[] edge : tightenedEdges) {
            int u = edge[0], v = edge[1];
            long w = distance[u][v];
            if (u == v && w < 0) { tightenedEdges.clear(); return false; }
            for (int i = 0; i < n; i++) {
                long diu = distance[i][u];
                if (diu == INF) continue;
                long[] di = distance[i];
                long newBase = diu + w;
                for (int j = 0; j < n; j++) {
                    long dvj = distance[v][j];
                    if (dvj == INF) continue;
                    long newDist = newBase + dvj;
                    if (newDist < di[j]) {
                        di[j] = newDist;
                        changed = true;
                        if (i == j && newDist < 0) { tightenedEdges.clear(); return false; }
                    }
                }
            }
        }
        if (closeThroughOrigin()) changed = true;   // hub: d[i][j] ≤ d[i][0] + d[0][j]
        for (int i = 0; i < n; i++) if (distance[i][i] < 0) { tightenedEdges.clear(); return false; }
        if (!changed) { tightenedEdges.clear(); return true; }
    }
    tightenedEdges.clear();
    return propagateFull();                          // rare exact fallback
}

4.3 O(1) infeasibility pre-check

Whether a single distance edge can be added is decidable in O(1) against the closed matrix — adding it is infeasible iff it closes a negative cycle: 

inf( from, to, min, max ) ⇔  max + d[to][from] < 0   or   −min + d[from][to] < 0

TemporalSolver.addConstraint now pre-checks every compiled edge and returns false before touching the matrix — no pollution, no rebuild. This matches the two pre-checks Meta-CSP's own incrementalDistanceMatrixComputation() performs. The routine rejection of infeasible resolvers dropped from an O(n³) rebuild to two array lookups.

4.4 Time-point pooling (mirrors Meta-CSP tpCreate / tpDelete)

freeTimePoint() neutralizes a row/column, reuses the lowest freed index on allocation, and shrinks the used range when the top index is freed — keeping the propagation/rebuild matrices compact.

4.5 Clean variable removal

TemporalSolver.removeVariable now drops the implicit duration edge (start ≤ end) recorded for every interval, frees the variable's two time points, and rebuilds so that closure paths through the freed points are recomputed (the same class of stale-state bug previously fixed for the live network and for retraction cleanup).

5. Regression test

SimpleTemporalNetworkIncrementalTest: ~5,500 randomized operations (constraint adds / removes / time-point creation, including interleaved creation) assert that every all-pairs bound queried from the incremental STN exactly equals an independent reference Floyd-Warshall closure over the same stored constraints — on successful and rejected operations alike. This test is what caught the origin-hub gap and the INF-sentinel overflow before they could affect the search.

  • 93/93 problems solve on both branches — 0 solvability differences.
  • 88/93 action sequences byte-identical; the 5 remaining mismatches are all the pre-existing, semantically-neutral leftArm1 ↔ rightArm1 flips in pick_up_object — unchanged by this work.
  • Full unit test suite green (./gradlew test), including the new randomized STN regression test.

7. What's left

  • The next hotspot is the symbolic solver. After this change, a JFR pass shows CompoundSymbolicSolver / SymbolicSolver (AC-3 style propagation) consuming ~40% of remaining samples — the largest remaining lever for further gains.
  • The incremental fixpoint's exactness is validated empirically (randomized stress test + full solver parity); pathological cascades fall back to full Floyd-Warshall.
  • Small benchmark problems (DWR-m_bring2, DWR-m_navigate1) show run-to-run timing noise from JIT warm-up and the global variable-ID counter, so their ±100% swings are measurement artifacts with identical plans.
